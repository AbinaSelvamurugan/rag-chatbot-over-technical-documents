# Threat model and security

Documents, HTML, PDF text and markdown are untrusted. They are displayed as inert text/code, never executed. Obvious role-spoofing and credential-exfiltration lines are filtered from LLM evidence (but retained in the original indexed excerpt). LangChain's prompt template places instruction hierarchy in a separate system message and encloses source excerpts inside labeled `source` blocks. A malicious document saying "ignore previous instructions" cannot modify server permissions. However model prompt-injection resilience is probabilistic, not mathematically guaranteed; the deterministic citation validator offers defense in depth.

Uploads: capped request-size read, allowlisted extension, PDF signature and text decoding checks, no HTML script rendering in UI, deterministic hashed storage paths, no arbitrary user-supplied filesystem path and no shell execution. Upload errors do not claim indexing success.

Network: URL ingestion disabled by default. Exact HTTPS host allowlist, DNS global-address checks, robots.txt fail-closed, no redirects, no environment proxies, bounded sizes/timeouts and MIME allowlist. **DNS rebinding/time-of-check vs time-of-use risk remains**; block private IP egress and cloud metadata hosts at the network firewall/egress proxy. Do not enable general-purpose arbitrary remote URLs.

Authentication: if `ADMIN_TOKEN` is nonempty it is required by protected API routes. It is a single shared token, **not per-user authorization**. No role hierarchy, rate limiting, audit server or CSRF/session-cookie system exists. Keep the default development host on loopback, supply HTTPS and access-control proxy externally, restrict CORS, and avoid placing a token in browser storage. Backend docs and document indexing should not be publicly exposed. The current UI accepts a token in memory, and sends it only in protected API request headers; use HTTPS for non-loopback access.

Privacy: sessions are UUID-scoped, SQLite stores up to 6 recent messages for query construction (historic messages may remain until cleanup), TTL is 12 hours evaluated on new session access, and explicit delete removes a session. There is no per-user identity. Raw document contents are not intentionally logged; filenames and processing state may be logged. Original uploads and indexes persist until deleted. Groq receives only the selected excerpts/question and recent limited context; confirm vendor data-processing terms for sensitive documentation.

Adversarial unit testing includes malicious passage text and citation fail-closed checks; tests do not prove resistance against all generated outputs. Suggested deployment controls: secret vault, least privilege, egress firewall, reverse-proxy rate limit, max concurrent indexing, backups, retention jobs, malware scanning, and encrypted persistent volume.
